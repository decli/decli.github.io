# decli.github.io

<https://decli.github.io/> —— 站点首页。

**这个仓库名不是随便起的，也改不了。** GitHub Pages 的用户站点只认一个仓库名：
`<用户名>.github.io`，一字不差。正是这个名字让根地址 `https://decli.github.io/` 存在。
换成任何别的名字，它就降级成子路径下的项目站点。

---

## 这一页在说什么

代码已不稀缺，判断才是。十五个作品，一行代码没写 —— 首页要让人**看见**这件事，而不只是读到它：

**光标是一枚透镜。** 移到哪里，哪里就露出画出它的那段真代码 —— 截图底下是画出那一屏的
源文件（信风看板底下就是 `src/pages/Dashboard.tsx`），页面底下是这一页自己的源码。
按 **X**，整页翻成它自己的代码。

**两种颜色，各管一件事。** 灰是 AI 的产出：代码、去了色的截图、所有的界面。
荧光黄是我的判断，只出现在我提的问题、我做的选择上。透镜底下，页面上我说的那几句话
是**同一位置、同一字形的黄色字符串**，两头多了引号 —— 你读到的那句话，就是代码里的一串字面量。

材质是看片灯：表面是灯箱的白，透镜里是 X 光片的蓝黑；截图四角的套准线、透镜外圈的刻度、
图注编号，都是看片灯上的东西。

## 怎么做出来的

这一页和十五件作品，都按同一套做法做出来：**一条流程、两层验证、三件事、一份记忆。**

- **一条流程。** 需求 → 设计 → 原型 → 编码 → 测试 → 部署，一步不少，执行全部交给 AI。
  人只在关键路径上拍板：做不做、选哪个、好不好用。
- **两层验证。** AI 先自己验 —— 跑测试、多种尺寸截图、生成物逐字节对一遍；人再当普通用户在线上用一遍。
  不逐行 Review，但确认环节一个不省。
- **三件事。** 人只做定方向、设规则、验结果。同一类错出现第二次，就不再只改那一处，而是改规则：
  写进 README，或者写成脚本 —— `tools/` 下切字、收代码、盖版本号的三个脚本都是这么来的。
- **一份记忆。** 文档和 git 记录是 AI 的记忆：README 写清楚规矩和来由，每个提交写清楚改了什么、为什么改。
  换一个会话接手，读完就能接着干，不用从头再讲一遍。

## 这里只放首页

```
index.html    首页
sites.js      ← 加一个项目只改这一个文件
shots/        产品截图（按 slug 分目录，webp）
icons/        没有 favicon 可借的项目的图标
code/         各项目的行数和代码摘录（tools/harvest.mjs 生成，见下）
fonts/        切好的字（tools/fonts.py 生成，见下）
tools/        stamp.py 资源版本号 · harvest.mjs 收代码 · fonts.py 切字
404.html      站点级 404（含单页应用的深链接兜底）
favicon.svg   深色片子上一圈荧光黄
og.png        分享图（1200×630，就是首屏）
robots.txt    站点级（爬虫只读根目录这一份）
```

没有依赖，没有框架，没有打包器。**改完直接推，推完直接生效。**

唯一一段自动化是推到 `main` 之后跑的 `tools/stamp.py`（GitHub Actions 自动执行并
回提交）—— 它只往 `index.html` / `404.html` 里写资源哈希，不改别的，也不生成任何产物。
删掉 `.github/workflows/stamp.yml` 这页照样能跑，只是资源缓存会顽固十分钟。

`code/` 和 `fonts/` 也是生成的，但**不在流水线里**：一个要去克隆十五个仓库，一个要原始字体，
都是改了相应东西之后手动跑一次、结果提交进来。忘了跑不会坏，只是旧（见下面各自那一节）。

各个项目**不在这里** —— 它们各自是独立仓库的项目站点，自己发自己的：

| 地址 | 来自 |
| --- | --- |
| `/` | 本仓库 |
| `/ftms/` | [decli/ftms](https://github.com/decli/ftms) |
| `/ems/` | [decli/ems](https://github.com/decli/ems) |
| `/wxformat3/` | [decli/wxformat3](https://github.com/decli/wxformat3) |
| `/logicc/` | [decli/logicc](https://github.com/decli/logicc) |

> 项目站点的路径**就是仓库名**，一字不差、不能自选 —— 想要 `/xxx/`，仓库就得叫 `xxx`。
> 这也是为什么 `ForeignTradeManagementSystem` 和 `ExportMarketingSystem` 改成了 `ftms` / `ems`。

## 加一个项目

只改 [`sites.js`](sites.js)：

```js
{
  slug: "xxx",                    // 短名。埋点靠它区分「点了哪个项目」
  cat:  "ext",                    // 分类，取 CATEGORIES 里的 key
  code: "src/main.ts",            // 代表这个项目的源文件，透镜和行数从这里摘（可选）
  name: { zh: "项目名", en: "Name" },   // 中英文同名就写一个字符串
  desc: { zh: "一句话说清它替谁解决什么", en: "…" },
  brief: { zh: "三十字上下的短句", en: "…" },   // 首页黄色那句，跟 GitHub 个人主页同一句
  tags: { zh: ["关键词"], en: ["Keyword"] },
  icon: "/xxx/favicon.svg",       // `/` 开头当图片；否则取 ICONS 里的图形
  href: "/xxx/",                  // 有在线地址才写。写了就带「在线」徽标、上首页版面
  dl:   "https://…/releases/latest",  // 装完才能跑的（原生 App）写这个，渲染成「下载」
  featured: true,                 // 没有在线地址也要上版面的（比如 codeless），单独标
  repo: "xxx",                    // GitHub 仓库名
  shots: [                        // 产品截图。没有就整条不写
    { src: "/shots/xxx/主界面.webp", code: "src/pages/Main.tsx", zh: "主界面", en: "Main view" },
  ],
}
```

**上版面的规则**：有 `href` 或 `dl`、或者标了 `featured`，并且有截图 —— 首页给它一整版；
其余的都在「全部」那张表里。分类、筛选、搜索、中英文、埋点全跟着数据走，`index.html` 一个字都不用动。

**截图上的 `code`** 是画出那一屏的源文件。透视的时候，截图底下露出来的就是它 ——
截图和代码得对得上，所以宁可不写也别乱写。路径后面可以带 `#关键词`，摘录从第一处出现它的那一行开始
（单文件应用用得上，比如思维小画本的 `index.html#10 方块拼拼`）。

加完之后，按需跑这几样（都是可选的，不跑也不会坏）：

```sh
node tools/harvest.mjs              # 行数和代码摘录：不跑，这个项目在透镜底下是空的、行数显示不出来
python3 tools/fonts.py --src <字体>  # 名字或文案里出现了新字：不跑，那几个字落到后备字体
python3 tools/stamp.py              # 忘了也行，推上去 Actions 会补
```

两件容易忘的配套：

- 新项目如果是**单页应用**，把前缀加进 `sites.js` 末尾的 `SPA_PREFIXES`，否则深链接刷新会 404
- 新项目如果有 **sitemap**，在 `robots.txt` 里加一行 `Sitemap:` —— 爬虫只读根目录这一份

**图标优先借子站自己的 favicon**（`/xxx/favicon.svg`），不要拿 emoji 顶替 ——
图标是产品的脸，首页摆一个跟站内对不上的，第一眼就露怯。

## 透镜是怎么做的

页面底下铺一整层「X 光片」（`#xr`），盖在内容上面，只在一个圆里露出来（`clip-path: circle()`）。
片子上每一块区域，换成画出它的真代码：

| 区域 | 换成什么 |
| --- | --- |
| 一整个区块（首屏、方法、作品、全部、版权页） | 这一页自己的源码里，属于这个区块的那几段 CSS / HTML / JS |
| 一句我说的话（标题、简介、每件作品的短句…） | 它在源码里的那串字符串：原样复制、同一位置、换成黄色、套上引号 |
| 作品的文字栏 | `sites.js` 里这个项目的那一条 |
| 一张截图 | 那个项目仓库里画出这一屏的源文件（`code/<slug>.json`） |

**区块和源码怎么对上**：源码里每个区块在 CSS、HTML、JS 三处各留了一个 `§名字` 的注释记号
（`/* ═══ §hero 首屏 ═══ */`、`<!-- §hero -->`、`// §hero`）。透镜从记号往下取到下一个记号，
三段拼起来就是「画出这一块的全部代码」。改结构的时候记号跟着走，别删 —— 删了也不报错，
只是那一块底下会接着显示别处的代码。

**这一页的源码从哪来**：就是 `fetch(location.pathname)`，拿到的是浏览器刚加载的那份 HTML。
所以透镜底下永远是线上这一版，行号也对得上（外圈底下那个 `index.html · L840` 就是真行号）。

**它跟着页面一起滚，而不是 fixed 再用 JS 追滚动。** 后者在异步滚动下会慢一帧，
透镜里的代码跟外面的界面就对不齐了。片子放在文档坐标里，只有圆心跟着指针动。

**三种待法**：开场停在标题开头（静态截图、分享图里也看得见：两个挂在页边的引号）；
鼠标一动就跟着指针；触屏上按住透镜能拖，松手后它留在那里，跟着页面走。
右下角那个圆钮（只在触屏上出现）和顶栏的「透视」、键盘 X 一样，是整页透视的开关。

**收起来的地方**：链接、按钮、输入框、缩略图条、整张「全部」表 —— 这些地方人要看字、要点东西，
透镜在上面缩成一个点，光标恢复原样。

**开场那道扫描线**：首屏从上往下扫一遍，扫过的地方先露一下底下的代码，然后透镜落位。
一次，一秒半，`prefers-reduced-motion` 下不扫，透镜直接停在原位，跟随也不带缓动。

**片子上几千个节点不是一开始就有的。** 每块区域的代码先只算好行，等透镜（或整页透视）
靠近了 —— 视口上下各多备一屏 —— 才真正放进 DOM。截图底下的摘录也是用到才去拿。
这一层整个 `aria-hidden`：它是给眼睛的，信息全在页面本身。

## 数字从哪来

首屏那个总数、每件作品「AI 写了多少行」、「全部」表里那根条的长度，全来自
[`tools/harvest.mjs`](tools/harvest.mjs) —— 它把仓库浅克隆下来，数一遍。

**怎么数：就是 `wc -l`。** git 里跟踪的每个文本文件数一遍换行符，二进制（图片、字体）跳过。
代码、文档、配置、部署脚本都算：需求文档和部署脚本也是 AI 写的，也是项目落地的一部分。
首屏对外只报一个量级（两位有效数字往下取整，带个 `+`），所以不抠细节；每件作品和条码上的是实数。

**数哪些仓库：我和 AI 提交过的全部仓库**，公开的、私有的都算（没提交过的 fork 不算）。
作品清单照旧只列公开的十五件；其余仓库在首屏那根条码上并成最后一段斜纹，`code/index.json` 里也只有一个合计
`others = { repos, loc, files }` —— 私有仓库的名字和代码都不出现在这个公开仓库里。

同时它从每件作品的仓库摘出截图对应的那几个源文件的开头一段（跳过文件头的 import 和版权注释），
存成 `code/<slug>.json` 给透镜用。加 `--skyline <文件>` 还会另存一份每一行源码的长度 ——
首页用不上，是给 GitHub 个人主页那卷「长卷」画远山用的。摘录和行长只看源码文件，不看文档、锁文件、生成物。

```sh
node tools/harvest.mjs                                # 自己把十五件作品克隆到临时目录
node tools/harvest.mjs --repos <目录>                  # 已经克隆好了
node tools/harvest.mjs --repos <目录> --others <目录>   # 再算上其余仓库；两个可以是同一个目录
```

没给 `--others` 就沿用上一次的合计，总数不会悄悄变少。

## 字

标题用**得意黑**（Smiley Sans），代码、标签和数字用 **Martian Mono**（宽度轴压到 75%～100%），
英文正文用 **Geist**；中文正文交给系统的苹方 / 思源黑体。全是 SIL OFL 1.1，允许子集化和自托管。

[`tools/fonts.py`](tools/fonts.py) 扫首页、404 和 `sites.js` 里出现过的字，切成 `fonts/` 下三个 woff2
（得意黑一百 KB 左右、另两个各二十 KB）。**不走 Google Fonts**：国内访问不稳，入口页不能把首屏押在别人的 CDN 上。
改了文案、出现了新字，重跑一次；没跑的话缺的字落到后备字体，不会显示成方块。

### 怎么摆

**一律去色。** 截图是 AI 的产出，跟代码一个颜色；指到那一版上，才回到原色。

**一版一件。** 上版面的作品左右交替排开：一边是名字、黄色那句短句、描述和按钮（文字栏粘在视口里），
一边是截图。截图下面一排缩略图，点哪张换哪张，透镜底下的源文件跟着换。点大图进全屏。

**cover 还是 contain，看裁掉的是哪一边。** 框是 16:10。跟框差不多宽或略窄的图 cover 顶对齐 ——
裁掉的是底部，页头和第一屏全在；比框还扁（思维小画本首页、MacPleco）或者竖得厉害（扩展的侧栏）的
contain，宁可留白，不砍内容。

**全屏大图分两档，点图切换。**「适应窗口」铺满可用宽度但放大不超过 1.5 倍；
点一下图切到「原始像素」，1:1 铺开、超出部分拖着看，底下还有一条「原图 ↗」直接开原文件。
关闭是「点图以外任何地方」+ ✕ + Esc；放大状态下拖动是平移，不翻页。
键盘：`←` `→` 翻页 · `Home` `End` 首末张 · `Esc` 退出，`Tab` 在对话框里循环，关掉后焦点回到点开它的地方。

### 加图

原图压到**长边 2560** 的 webp（quality 72），扔进 `shots/<slug>/`，
再往 `sites.js` 那条记录里加 `shots`（记得带上 `code`）。**第一张是封面**，挑最能说明「这是什么」的那张。

**2560 这个数不是拍脑袋的。** 全屏大图最宽会到 1240 CSS px，2 倍屏上就是 2480 个物理像素；
出图小于这个数，浏览器就得放大，放大就是糊。只出一套高清，不做 srcset 两套：
截图本来就是滚到才下载的，1 倍屏用户多下一点，换掉的是「所有 2 倍屏用户看到的都是糊的」。

## 缓存与版本号

**GitHub Pages 给所有响应发 `Cache-Control: max-age=600`，而且不支持自定义响应头。**
这个 600 秒改不掉 —— 没有 `_headers`，没有服务端配置，什么招都没有。

但浏览器的缓存是**按 URL 存的**，URL 变了就是另一个资源，当场重新下。
所以 `tools/stamp.py` 给每个会变的资源（`sites.js`、`shots/`、`icons/`、`code/`、`fonts/`）
算一个内容哈希，写成一张表塞进 `index.html`：

```html
<!-- ASSET-VERSIONS:BEGIN -->
<script>window.ASSET_V = { "/sites.js": "4f3238e0", "/code/ftms.json": "51126932", … };</script>
<!-- ASSET-VERSIONS:END -->
```

页面里的 `V()` 查这张表拼出 `/code/ftms.json?v=51126932`。表里没有的原样返回 ——
子站 favicon 归各自仓库管，外链图更轮不到这边定。表整个不存在也不报错，就是退回没有版本号的状态。

**字体单独处理。** CSS 里的 `url(/fonts/x.woff2)` 和 `<link rel="preload">` 在 JS 跑起来之前就要用，
进不了 `V()`，所以 stamp.py 直接改这两处的地址（`index.html` 和 `404.html` 都改）——
而且两处必须是同一个地址，不然预加载的那份白下了。

**说清楚它治不了什么：`index.html` 自己。** 它是入口，URL 不能带哈希，
所以推上去之后最多有 10 分钟旧副本还在浏览器和 CDN 里。这一段只能硬刷新
（Cmd/Ctrl+Shift+R）或者等。版本号解决的是另外半件事：
**新 HTML 到了之后，别再配一份旧的 JS、旧的字和旧的代码摘录。**

**为什么交给 Actions 而不是让人手动跑。** 手动跑一个脚本才生效，等于把「忘了跑」
变成一类线上 bug，症状还正好是最难查的那种。流水线跑，`改完直接推` 这句话才还成立。
回提交带 `[stamp]` 标记，带这个标记的 push 直接跳过，不会自己触发自己。

## 几个不显眼但重要的地方

**深链接兜底。** `/ftms/` 是单页应用，刷新 `/ftms/follow-ups` 会走 404 流程。正常情况下
Pages 回落到那个项目站点自己的 `404.html`，走不到这儿。但「Pages 会不会替子目录去找最近的
404.html」官方说得并不硬，一旦不这么做就是**所有深链接刷新全 404**。所以 `404.html` 里补了
一道：把原始路径记进 `sessionStorage` 再跳回子站首页，应用启动时 `replaceState` 还原。
其中 `p !== prefix` 那半句是防死循环的 —— 少了它，子站真挂掉时浏览器会一直转圈。
404 本身也用同一套材质：一枚停着的透镜，底下是这个地址该有、却没有的那段代码。

**访问统计。** 首页和各子站共用同一个 GA4 property（`G-Y7H2JMNX74`）。同域下 GA4 靠域名级
`_ga` cookie 认人，一个 property 才能把「从首页点进 ftms、退出来又去了 ems」看成一次会话、
一条路径。分站靠 `site` 参数和 `page_path` 前缀在报表里切开。开了「请勿跟踪」就不发。
首页记的事件：`open_project`（点了哪个、是体验还是源码还是下载）、`preview_project`、
`filter_category`、`switch_language`、`switch_theme`，以及 `xray_toggle`（整页透视开 / 关）。

**版权邮箱画在 canvas 上。** 页脚那个邮箱不是文本节点，源码里也没有可直接正则捞走的字面量，
更没写进 `aria-label` / `title`。补偿：整块可点击复制，读屏用户拿到的是可粘贴的真地址。

**中英文。** 默认跟浏览器语言走（`navigator.language` 不是中文就开英文），
手动切过就记住，之后不再猜。界面词条在 `index.html` 的 `I18N` 里，
项目自己的名字和描述在 `sites.js` 里 —— 谁的文案归谁管。

**子站一律新标签打开**（`target="_blank"` + `rel="noopener noreferrer"`）。
入口页的作用是分发，不是拦路：从这儿点走的人多半还要回来看第二个。

**荧光笔是滚到才划的。** 首屏以外的那几道黄，先收成零宽，进了视口再从左往右划开；
`IntersectionObserver` 不在、或者减弱动效时，一直是划好的 —— 黄色是信息，不能因为动效没跑就没了。
「方法」那条灰色的轨道也一样：滚到才一根根长出来，长到哪儿，哪儿的黄线才落下。

**首屏标题必须两行写完。** 字号跟着标题那 8 栏的实际宽度算（`calc(... * 0.104)`），每行 `nowrap` ——
「代码已不稀缺，」要是折出第三行，那个「缺」孤零零掉下去，整句话的力气就散了。

**键盘。** `/` 聚焦搜索 · `Esc` 清空退出 · `X` 整页透视（再按一次或 `Esc` 收起）。
大图开着的时候键盘归它管。

**这一页还是只做一件事：把人分发到各个项目去。** 透镜不是另一个玩意儿，它是首屏
「我写的代码 0 行」的证据 —— 每一个入口底下，都摆着它自己的代码。曾经加过戳泡泡和连连看，都拿掉了；
要往上加东西之前，先问一句：它让「人出判断，AI 执行」更可信了吗？
