# decli.github.io

<https://decli.github.io/> —— 站点首页。

**这个仓库名不是随便起的，也改不了。** GitHub Pages 的用户站点只认一个仓库名：
`<用户名>.github.io`，一字不差。正是这个名字让根地址 `https://decli.github.io/` 存在。
换成任何别的名字，它就降级成子路径下的项目站点。

---

## 这里只放首页

```
index.html    首页
sites.js      ← 加一个项目只改这一个文件
shots/        产品截图（按 slug 分目录，webp）
icons/        没有 favicon 可借的项目的图标
tools/        stamp.py：给静态资源盖内容版本号（见下）
404.html      站点级 404（含单页应用的深链接兜底）
robots.txt    站点级（爬虫只读根目录这一份）
```

没有依赖，没有框架，没有打包器。**改完直接推，推完直接生效。**

唯一一段自动化是推到 `main` 之后跑的 `tools/stamp.py`（GitHub Actions 自动执行并
回提交）—— 它只往 `index.html` 里写一张资源哈希表，不改别的，也不生成任何产物。
删掉 `.github/workflows/stamp.yml` 这页照样能跑，只是资源缓存会顽固十分钟。

各个项目**不在这里** —— 它们各自是独立仓库的项目站点，自己发自己的：

| 地址 | 来自 |
| --- | --- |
| `/` | 本仓库 |
| `/ftms/` | [decli/ftms](https://github.com/decli/ftms) |
| `/ems/` | [decli/ems](https://github.com/decli/ems) |
| `/wxformat3/` | [decli/wxformat3](https://github.com/decli/wxformat3) |

> 项目站点的路径**就是仓库名**，一字不差、不能自选 —— 想要 `/xxx/`，仓库就得叫 `xxx`。
> 这也是为什么 `ForeignTradeManagementSystem` 和 `ExportMarketingSystem` 改成了 `ftms` / `ems`。

这个仓库一度还兼着「产物仓库」，`ftms/`、`ems/` 两个目录由各自的项目用脚本推进来。
改成项目站点之后那套跨仓库部署整个不需要了 —— 一个项目一个仓库，各自发各自的。

## 加一个项目

只改 [`sites.js`](sites.js)：

```js
{
  slug: "xxx",                    // 短名。埋点靠它区分「点了哪个项目」
  cat:  "ext",                    // 分类，取 CATEGORIES 里的 key
  name: { zh: "项目名", en: "Name" },   // 中英文同名就写一个字符串
  desc: { zh: "一句话说清它替谁解决什么", en: "…" },
  tags: { zh: ["关键词"], en: ["Keyword"] },
  icon: "/xxx/favicon.svg",       // `/` 开头当图片；否则取 ICONS 里的图形 + tint 上色
  href: "/xxx/",                  // 有在线地址才写。写了就自动排前面、占两格、带「在线」徽标
  dl:   "https://…/releases/latest",  // 装完才能跑的（原生 App）写这个，渲染成「下载」
  repo: "xxx",                    // GitHub 仓库名
  shots: [                        // 产品截图。没有就整条不写，卡片上不会出现预览入口
    { src: "/shots/xxx/主界面.webp", zh: "主界面", en: "Main view" },
  ],
}
```

`href` 和 `dl` 是两回事，别混：`href` 是**点开就能试**，带「在线」徽标、占两格、
计进首屏那个「N 个可在线体验」；`dl` 只是个安装包地址，什么都不占。

分类、筛选、搜索、中英文、埋点全跟着数据走，`index.html` 一个字都不用动。

**图标优先借子站自己的 favicon**（`/xxx/favicon.svg`），不要拿 emoji 顶替 ——
图标是产品的脸，首页摆一个跟站内对不上的，第一眼就露怯；借它自己的还能永远不跑偏。
没有 favicon 的（扩展、脚本、App）用 `ICONS` 里的线条图形配 `tint` 上色：
emoji 在 Windows / Mac / Android 上长得完全不一样，一排摆开必然花。

两件容易忘的配套：

- 新项目如果是**单页应用**，把前缀加进 `sites.js` 末尾的 `SPA_PREFIXES`，否则深链接刷新会 404
- 新项目如果有 **sitemap**，在 `robots.txt` 里加一行 `Sitemap:` —— 爬虫只读根目录这一份

## 产品截图

鼠标停在卡片底部按钮右边那条空白上，卡内展开截图；点一下（或键盘回车、
手机轻点）进全屏大图。**13 个项目里 8 个有图，25 张，加起来 2.1 MB。**

### 图从哪来

一张都不是画的示意图，全来自项目本身：

| 项目 | 来源 |
| --- | --- |
| ftms · ems · wxformat3 | 本地起服务跑真实构建产物，Playwright 逐页截图 |
| macpleco · ip-geo（弹窗） | 项目仓库 README 里现成那几张 |
| jobornot · ip-geo（设置） | Chromium 加载未打包扩展，直接开 `chrome-extension://` 那几个页面 |
| pagescroll | 把用户脚本按 `document-start` 注进真实网页（就是这一页），截控件那一角 |

**剩下 5 个没有，是真的没法有，不是漏了：**
TabInfoCopy 从头到尾没有界面（点图标即复制，连提示都不弹）；公众号数据导出和
Bing 壁纸批量下载得先登录到目标站点才有东西可看；取件码助手和老爸下象棋是安卓应用，
手上没有模拟器。宁可让这几张卡片没有预览入口，也不摆一张摆拍出来的示意图。

> 取件码助手是个例外：它 README 里那张手机截图存在 GitHub 附件上，下载不到，
> 于是 `sites.js` 里**直接引的那个外链**。取不到就自动消失（见下），
> 想要它跟别的一样稳，把图存进 CodeHelper 仓库、再换成 `/shots/` 下的本地副本。

### 加图

原图压到**长边 2560** 的 webp（quality 72），扔进 `shots/<slug>/`，
再往 `sites.js` 那条记录里加 `shots`。**第一张是封面**，挑最能说明「这是什么」的那张。
加完跑一次 `python3 tools/stamp.py`（忘了也行，推上去 Actions 会补）。

**2560 这个数不是拍脑袋的。** 全屏大图最宽会到 1240 CSS px，2 倍屏上就是 2480 个
物理像素；出图小于这个数，浏览器就得放大，放大就是糊 —— 一开始按 1200 出图，
等于在大图里放大 2.07 倍，糊得一眼能看出来。截图本身也得够：Playwright 那边
`deviceScaleFactor` 拉到 2～3，1440×900 的视口出来是 2880×1800。

**只出一套高清，不做 srcset 两套。** 两套等于仓库里两份文件、五六兆。图本来就
只在鼠标停上去时才下载，1 倍屏用户多下一点，换掉的是「所有 2 倍屏用户看到的都是糊的」。

**大图分两档，点图切换。**「适应窗口」铺满可用宽度但放大不超过 1.5 倍（1.5 倍是
有点软，不是糊；再往上就明显了，2560 那批图根本轮不到放大）；点一下图切到
「原始像素」，1:1 铺开、超出部分拖着看，底下还有一条「原图 ↗」直接开原文件。

这里踩过一个坑：一开始写的是「绝不放大 + 点图关闭」。结果 1600 宽的原图
（MacPleco、IP 归属地弹窗）在 2 倍屏上只能占 800 CSS px，一张小图浮在一大片黑里，
而点它只会关掉 —— **等于把「看大图」这件事整个弄没了**。清楚和看得清不是一回事：
默认那一档得先把画面撑起来，想抠细节的人再点进 1:1。

关闭改成「点图以外任何地方」+ ✕ + Esc。别只认最外层那个容器 —— 图铺满之后
它露在外面的部分只剩几十像素，「点旁边退出」等于没有。
放大状态下拖动是平移，不翻页；拖完浏览器不一定补一个 click，所以那个
「刚才是拖动」的标记要排到 click 之后主动清掉，不然会把下一次点击白白吃掉。

### 几个不显眼但重要的地方

**图一律用到才下载。** 这一页本来只有一个 HTML 文件，25 张截图跟着首屏发等于把
零依赖的入口页做成图库。所以 `<img>` 出厂时没有 `src`，展开才填。预取踩人的动作节奏：
指针一进卡片就悄悄下封面那张（这会儿人还在往按钮那边走），翻到第 i 张顺手把 i±1 也下了。
等指针真停到「预览」上，图基本已经在缓存里。

**入口挂在按钮右边那条空白上。** 卡片底部那行左边是「打开 / 源码」，右边一直空着 ——
那是卡片上唯一一处没在说事的地方。同时它是个**真按钮**：不给实体的话，
「这儿能停鼠标」没人知道，而且键盘和触屏就彻底进不来了。三种设备三条路：
鼠标停上去展开卡内预览、键盘 Tab 到它回车进大图、触屏没有 hover 点一下直接进大图。

**卡内预览不盖住底部那一行。** 盖住就等于把两个主按钮埋了 —— 鼠标要走到面板上才能翻页，
而面板正压在按钮上。所以面板下沿停在 `--acts-h` 上方，预览开着时按钮照样能点。

**cover 还是 contain，看裁掉的是哪一边。** cover 总从图相对更大的那条边上裁：
图比框更扁就裁两侧（侧栏、右边那列全没了，不行），图比框更方更竖就裁上下
（配顶对齐，留下的正好是页头和第一屏，界面的身份全在那儿，可以）。
所以只在「裁上下」那一档用 cover，其余一律 contain —— 宁可留白，不砍内容。
这个判断要拿框的实际宽高比算，写死「横图 cover 竖图 contain」在两格宽的卡片上就翻车。

**图挂了就当它没有过。** 加载失败的那张从清单里摘掉、入口上的计数改对；
一张不剩就连入口一起撤 —— 与其留个点开是空的按钮，不如不留。

**有截图的卡片有 `min-height`，而且只在有悬停的设备上加。** 不给的话预览面板只剩 160px，
横屏截图裁到只认得出个导航条。手机上展不开卡内预览，那几十像素纯粹是段空当，
白让人多划一屏，所以裹在 `@media (hover: hover)` 里。

## 缓存与版本号

**GitHub Pages 给所有响应发 `Cache-Control: max-age=600`，而且不支持自定义响应头。**
这个 600 秒改不掉 —— 没有 `_headers`，没有服务端配置，什么招都没有。

但浏览器的缓存是**按 URL 存的**，URL 变了就是另一个资源，当场重新下。
所以 `tools/stamp.py` 给每个会变的资源算一个内容哈希，写成一张表塞进 `index.html`：

```html
<!-- ASSET-VERSIONS:BEGIN -->
<script>window.ASSET_V = { "/sites.js": "4f3238e0", "/shots/ftms/dashboard.webp": "51126932", … };</script>
<!-- ASSET-VERSIONS:END -->
```

页面里的 `V()` 查这张表拼出 `/shots/ftms/dashboard.webp?v=51126932`。
换了图、改了 `sites.js`，哈希跟着变，新地址当场生效。表里没有的原样返回 ——
子站 favicon 归各自仓库管，外链图更轮不到这边定。表整个不存在也不报错，
就是退回没有版本号的状态。

**说清楚它治不了什么：`index.html` 自己。** 它是入口，URL 不能带哈希，
所以推上去之后最多有 10 分钟旧副本还在浏览器和 CDN 里。这一段只能硬刷新
（Cmd/Ctrl+Shift+R）或者等 —— 仓库这边做什么都没用。版本号解决的是另外半件事：
**新 HTML 到了之后，别再配一份旧的 JS 和旧的图。** 那种错配比单纯慢十分钟难查得多：
页面是新的，数据是旧的，什么都不报错。

**为什么交给 Actions 而不是让人手动跑。** 手动跑一个脚本才生效，等于把「忘了跑」
变成一类线上 bug，症状还正好是最难查的那种。流水线跑，`改完直接推` 这句话才还成立。
回提交带 `[stamp]` 标记，带这个标记的 push 直接跳过，不会自己触发自己。
Actions 关了也不影响正确性 —— 自己跑 `python3 tools/stamp.py` 再推，效果一样。

## 几个不显眼但重要的地方

**深链接兜底。** `/ftms/` 是单页应用，刷新 `/ftms/follow-ups` 会走 404 流程。正常情况下
Pages 回落到那个项目站点自己的 `404.html`，走不到这儿。但「Pages 会不会替子目录去找最近的
404.html」官方说得并不硬，一旦不这么做就是**所有深链接刷新全 404**。所以 `404.html` 里补了
一道：把原始路径记进 `sessionStorage` 再跳回子站首页，应用启动时 `replaceState` 还原。
其中 `p !== prefix` 那半句是防死循环的 —— 少了它，子站真挂掉时浏览器会一直转圈。

**访问统计。** 首页和各子站共用同一个 GA4 property（`G-Y7H2JMNX74`）。同域下 GA4 靠域名级
`_ga` cookie 认人，一个 property 才能把「从首页点进 ftms、退出来又去了 ems」看成一次会话、
一条路径。分站靠 `site` 参数和 `page_path` 前缀在报表里切开。开了「请勿跟踪」就不发。

**版权邮箱画在 canvas 上。** 页脚那个邮箱不是文本节点，源码里也没有可直接正则捞走的字面量，
更没写进 `aria-label` / `title`。邮箱以文本形态出现在公开网页上，半天就会进群发名录。
补偿：整块可点击复制，读屏用户拿到的是可粘贴的真地址，而爬虫不会去点按钮。

**中英文。** 默认跟浏览器语言走（`navigator.language` 不是中文就开英文），
手动切过就记住，之后不再猜。界面词条在 `index.html` 的 `I18N` 里，
项目自己的名字和描述在 `sites.js` 里 —— 谁的文案归谁管。

**子站一律新标签打开**（`target="_blank"` + `rel="noopener noreferrer"`）。
入口页的作用是分发，不是拦路：从这儿点走的人多半还要回来看第二个。

**背景。** 三团大色斑缓慢漂浮，外加一团跟着指针走的高光。透明度压得很低
（亮色 0.022~0.065、暗色 0.028~0.085，模糊 96px；
实测背景最多偏离底色 14 级、平均 5 级左右）—— 入口页的底色是给内容让路的，
一眼能看出「在渐变」就已经太重了。极光的漂浮和视差**必须拆到两层元素上**：
挤在同一个元素上时，`animation` 里的 transform 会把 JS 写的那个整帧覆盖掉，
视差看着完全没生效，而且不报任何错。

指针跟随是**按需排帧**的：`pointermove` 一秒能来一百多次，直接写 style 会让整页
跟着抖，所以只记坐标、攒到下一帧再写；指针不动就一帧都不排，页面闲着时这段代码
等于不存在。`prefers-reduced-motion` 下整套不启动，内容一个不少。

**这一页只做一件事：把人分发到各个项目去。**
曾经加过戳泡泡和连连看，都拿掉了 —— 入口页多一个玩意儿，主线就模糊一分。

**键盘。** `/` 聚焦搜索 · `Esc` 清空退出。跟 `/ftms/` 的习惯一致。
大图开着的时候键盘归它管：`←` `→` 翻页 · `Home` `End` 首末张 · `Esc` 退出，
`Tab` 在对话框里循环，关掉后焦点回到点开它的那个按钮。
鼠标：点图在「适应窗口 / 原始像素」之间切，放大后拖着平移，点图以外的地方退出。
