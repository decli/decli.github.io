# 首页交互形态草案 · 三选一

> 2026-08 · 针对 <https://decli.github.io/> 首页的交互形态探索。
> 本目录是**设计工作材料**，只活在这个分支上，不参与部署；三个 HTML 都是可直接双击打开的自包含原型（`noindex`，内联全部样式脚本，图标在站外环境自动退化为内置图形）。

---

## 一、现状诊断

当前首页：大标题 + 搜索/分类筛选 + 卡片网格，辅以极光背景、指针跟随光晕、卡片光晕。它已经做对了很多事——**单一职责（分发）、零依赖单文件、中英文、明暗、键盘 `/`、克制的动效预算**。这些是资产，三个草案全部继承。

对照 2025–2026 的行业走向，有三处值得再想：

1. **「搜索 + 筛选 + 网格」是工具页的默认形态**，可靠但无记忆点。12 个项目跨度极大（外贸系统 ↔ 老爸象棋），网格把它们摆成了同质的商品墙，「为什么长在一起」这条线（嫌麻烦→自己写）只活在标题里，没活在交互里。
2. **指针跟随渐变（spotlight）正在退潮**——brittanychiang 带火后克隆泛滥，已从「亮点」变成「见过」。它不再为页面挣分。
3. 卡片网格里**「能打开的」和「只有源码的」权重差**只靠占格数表达；首访者第一眼仍要自己扫描 12 张卡才能建立全貌。

## 二、调研综述（要点）

两路实际调研（个人作品集 / 商业产品站），结论收敛为：

- **编辑部式极简在上升**：paco.me、leerob（2024–25 重构主题就是删花活）、read.cv 遗产范式——排版即设计，列表优先于卡片墙。
- **被验证最多的列表交互**：brittanychiang 的「行式列表 + 悬停时其余行整体退后」，成本极低、质感极高，是被克隆最多的开发者主页范式。
- **命令面板（⌘K）的真实位置**：产品里是标配（Linear/Vercel/Figma），但 GitHub 2025 年曾以「低使用率」为由下线 ⌘K（抗议后撤回）。结论：**⌘K 不能作为隐藏彩蛋，要么就把面板本身摆成页面主体**，浏览模式（空查询=全量列表）必须是默认态。
- **叙事滚动的合理剂量**：任务型页面整页 scrollytelling 是负资产；正确用法是 IntersectionObserver 只切 class + CSS 做入场，配常驻「跳过/直达」出口，`prefers-reduced-motion` 折叠为完整静态文档。
- **低成本高记忆点的三件套**：antfu 式 View Transitions 圆形扩散换主题、逐行 stagger 入场、kbd 键位徽章。
- **退潮清单**：静态 bento 小方块墙、光标替换、长预加载、scroll-jacking、spotlight 光标渐变。

## 三、三个草案

三个方案覆盖了三种根本不同的「页面性格」，而不是三种配色：

| | A 启动台 | B 索引页 | C 问题墙 |
| --- | --- | --- | --- |
| 性格 | 工具（键盘/效率） | 文档（排版/克制） | 叙事（故事/人格） |
| 隐喻 | Raycast / Spotlight | 一页排得讲究的目录 | 一条「麻烦→答案」时间线 |
| 最优访客 | 回访者、工程师 | 扫读者、同行、招聘 | 首访者、社交分享 |
| 与现状的距离 | 演进（搜索升为主体） | 重构（去卡片化） | 重构（结构=口号） |

### 方案 A 「启动台」 `a-launcher.html`

**一句话**：页面即命令面板——搜索从工具条升格为页面主体，落地即可打字。

```
┌──────────────────────────────────────────────┐
│  d decli                     GitHub  ◐       │
│                                              │
│          嫌它麻烦，就自己写一个                │
│          12 个项目 · 3 个在线                 │
│  ╔══════════════════════════════════════════╗│
│  ║ 🔍 想做什么？搜用途，也搜名字…        / ║│
│  ╟──────────────────────────────────────────╢│
│  ║ 试试 [排版公众号][代理生效没][给爸妈用]… ║│ ← 意图芯片
│  ╟──────────────────────────────────────────╢│
│  ║ 全部12 在线应用3 扩展5 脚本2 应用2       ║│
│  ╟──────────────┬───────────────────────────╢│
│  ║ ▸ 信风    ● ↵│  [图标] 信风 Tradewind    ║│
│  ║   EMS     ●  │  外贸业务全流程管理……      ║│
│  ║   WxMark  ●  │  [外贸管理][跟单][退税]    ║│
│  ║   IP 归属地  │                           ║│
│  ║   …          │  [打开 ↗] [源码]          ║│
│  ╟──────────────┴───────────────────────────╢│
│  ║ ↑↓ 选择 · ↵ 打开 · Esc 清空       12/12 ║│
│  ╚══════════════════════════════════════════╝│
└──────────────────────────────────────────────┘
```

**签名交互**
- **意图芯片**：按「你想干什么」搜，不按「项目叫什么」搜。「排版公众号」「代理生效没」是访客脑子里的词，芯片把这层翻译显性化，同时兼作空状态的救生圈。
- 完整键盘流：落地自动聚焦（仅桌面），`↑↓` 选、`↵` 开、`Esc` 清、`/` 回焦；悬停即选中，双通道一致。
- 右侧预览面板随选中项实时切换（120ms 淡入），把「点开卡片才知道详情」变成「扫一眼列表就看完 12 个」。
- 空闲时占位符轮换文案，持续教「按用途搜」。

**关键取舍**：浏览模式必须是默认态（空查询=全量分组列表），否则重蹈 GitHub ⌘K 低使用率的覆辙；移动端预览面板收起，行本身变成两行卡直接可点。风险：形态偏「工程师趣味」，对非技术访客（外贸用户、家人朋友）陌生感最强。

### 方案 B 「索引页」 `b-index.html`

**一句话**：内容即界面——没有卡片没有按钮墙，一页排得讲究的目录，装饰预算只花在三处。

```
┌────────────────────────────┬────────────────┐
│ decli        GitHub 明暗   │                │
│                            │  ┌──────────┐  │
│ 嫌它麻烦，                  │  │ [图标]    │  │
│ 就自己写一个。（衬线大字）    │  │ 职得投    │  │
│                            │  │ 简历和 JD │  │
│ 这里是十二个这样的东西：      │  │ 摆一起比…│  │
│ 3̲个̲在̲线̲应̲用̲、5̲个̲浏̲览̲器̲扩̲展̲、 │  │ [求职][AI]│  │
│ 2̲个̲用̲户̲脚̲本̲和2̲个̲移̲动̲应̲用̲。  │  │ 打开↗ 源码│  │
│      ↑ 正文数字即筛选器      │  └──────────┘  │
│ ──────────────────────────  │   ↑ 预览窗     │
│ 01 信风 Tradewind ● 外贸…↗  │   (sticky,     │
│ 02 EMS 外贸营销系统 ● AI…↗  │    随悬停换)   │
│ 03 WxMark ● 公众号排版…  ↗  │                │
│ 04 IP 归属地监控  工具栏…↗  │                │
│ 05 职̲得̲投̲ ̲J̲o̲b̲O̲r̲N̲o̲t̲ ←hover │                │
│    （其余行整体退后 38%）     │                │
│ …                          │                │
└────────────────────────────┴────────────────┘
```

**签名交互**
- **正文数字即筛选器**：介绍句里的「5 个浏览器扩展」本身就是按钮，点了列表只亮这一类——筛选器不再是一排胶囊，而是一句话。压暗不移除（0.16 透明度），页面永不跳动。
- **brittanychiang 手法**：悬停一行，其余行整体退后；行内名称、序号、箭头同步点亮。
- **sticky 预览窗**：右栏一格固定卡片随悬停/键盘焦点切换内容，「悬停即看完」且不跟着光标乱飞。
- **圆形扩散换主题**：View Transitions 从点击处荡开（antfu 式），是全页唯一的「炫技」，不支持的浏览器直接切换。
- 逐行 35ms stagger 入场，只在首次加载出现一次。

**关键取舍**：信息密度与克制感最高，实现也最薄（首屏几乎纯排版）；代价是触屏没有悬停——移动端行尾加「＋」展开详情，预览窗隐藏。搜索框被删掉了（12 行一屏可扫完）；若未来项目到 20+，需要把 `/` 搜索请回来。

### 方案 C 「问题墙」 `c-story.html`

**一句话**：把口号当字面结构——每个项目都是一句抱怨的答案，滚动翻故事，随时可跳出。

```
┌──────────────────────────────────────────────┐
│ decli                        GitHub 明暗     │
│                                              │
│   嫌它麻烦，                                  │
│   就自己写一个。（衬线特大字）        [进度轨] │
│   [看它们怎么来的 ↓] [直接挑工具]        ●    │
│ ─────────────────────────────────        ○    │
│ │ 替自己省事 · 在线应用                  ○    │
│ ●                                        ○    │
│ │ 「订单一多，Excel 就开始打架：          …    │
│ │   报价一版、跟单一版、退税又一版        ⊞    │
│ │   —— 哪版是真的？」                         │
│ │  —— 于是有了                                │
│ │  ┌────────────────────────────┐             │
│ │  │[图标] 信风 Tradewind ·在线  │→            │
│ │  │外贸全流程：询盘到退税……     │             │
│ │  └────────────────────────────┘             │
│ ●  「找买家一个工具、发信一个工具…」           │
│ │   …（× 11 步，滚动逐一入场）                │
│ ─────────────────────────────────             │
│  十二个，全在这。（紧凑瓦片 × 12）             │
└──────────────────────────────────────────────┘
```

**签名交互**
- **「麻烦 → 于是有了 → 答案卡」**：11 句口语抱怨串成一条左缘脊线时间线，走到哪、节点亮到哪。文案是主角——这个方案的成败在写作，不在代码。
- **合理剂量的滚动**：IntersectionObserver 只切 class，CSS 做 550ms 入场；不劫持滚轮、不做视差；`prefers-reduced-motion` 下全部直接可见。
- **三层逃生舱**：首屏「直接挑工具」、滚过首屏后浮出的常驻「全部工具」胶囊、右缘 12 点进度轨（悬停出名字、点击跳转）——任务型访客永远一步可达全量索引。
- 结尾「十二个，全在这」紧凑瓦片墙 = 回访者的快速通道。

**关键取舍**：人格表达与记忆点最强，最适合首访/分享/招聘场景；分发效率天然最低（靠三层逃生舱补），滚动长度 ≈ 5–6 屏。IP Display 并进 IP 归属地监控那一步做附注，避免 12 步过长。分类在故事里改叫「替自己省事 / 顺手写的 / 给家里人」——按动机分，比按技术形态分更贴这个形态。

## 四、逐项对比

| 维度 | A 启动台 | B 索引页 | C 问题墙 |
| --- | --- | --- | --- |
| 分发效率（回访） | ★★★★★ 三次击键直达 | ★★★★ 一屏扫完 | ★★★ 靠结尾索引 |
| 首访全貌建立 | ★★★★ 列表+预览 | ★★★★★ 12 行一屏 | ★★★ 需滚完或跳过 |
| 人格/记忆点 | ★★★ 工程师趣味 | ★★★★ 克制的自信 | ★★★★★ 有故事 |
| 移动端体验 | ★★★★ 退化为列表 | ★★★★ 行内展开 | ★★★★★ 天然竖读 |
| 实现/维护成本 | 中（键盘态机） | 低（几乎纯排版） | 中（IO + 文案维护） |
| 对非技术访客 | 弱 | 中 | 强 |
| 加新项目的成本 | 改数据即可 | 改数据即可 | 要写一句好抱怨 |
| SEO/无 JS 退化 | 中（列表仍在 DOM） | 好（纯文档流） | 好（JS 挂了=完整长文） |

## 五、推荐

**首选 B「索引页」**：与站点现有的克制哲学同频（「入口页多一个玩意儿，主线就模糊一分」），把 12 个项目的全貌压进一屏，实现最薄、退化最优雅；「正文数字即筛选器」和「圆形换主题」提供了恰好一份的记忆点。

**若更看重「让人记住这个人」**，选 C——它是唯一把「嫌它麻烦，就自己写一个」从口号变成结构的方案，代价是分发让位于叙事。

**可混搭**（三个方案的零件互相兼容）：
- A 的「意图芯片」可以嫁接进 B 的介绍段下方或现有首页搜索框下方；
- B 的「圆形扩散换主题」「行悬停退后」可以直接给现首页低成本升级；
- C 的「一句抱怨」可以作为 B 列表行的悬停预览文案（预览窗里先给抱怨、再给简介）。

```

open design/homepage-concepts/a-launcher.html
```

原型统一为中文单语、不落存储、不埋点；正式实施时继承现首页的 i18n / GA4 / 邮箱防爬 / `SPA_PREFIXES` 等既有机制。图标在站内环境自动借用各子站真实 favicon（`onerror` 退化为内置图形），与现首页同一策略。
