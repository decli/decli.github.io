# decli.github.io

<https://decli.github.io/> —— 站点首页。

**这个仓库名不是随便起的，也改不了。** GitHub Pages 的用户站点只认一个仓库名：
`<用户名>.github.io`，一字不差。正是这个名字让根地址 `https://decli.github.io/` 存在。
换成任何别的名字，它就降级成子路径下的项目站点。

---

## 这里只放首页

```
index.html    首页
sites.js      ← 加一个项目只改这一个文件
404.html      站点级 404（含单页应用的深链接兜底）
robots.txt    站点级（爬虫只读根目录这一份）
```

没有构建步骤，没有依赖。**改完直接推，推完直接生效。**

各个项目**不在这里** —— 它们各自是独立仓库的项目站点，自己发自己的：

| 地址 | 来自 |
| --- | --- |
| `/` | 本仓库 |
| `/ftms/` | [decli/ftms](https://github.com/decli/ftms) |
| `/ems/` | [decli/ems](https://github.com/decli/ems) |
| `/wxformat3/` | [decli/wxformat3](https://github.com/decli/wxformat3) |

> 项目站点的路径**就是仓库名**，一字不差、不能自选 —— 想要 `/xxx/`，仓库就得叫 `xxx`。
> 这也是为什么 `ForeignTradeManagementSystem` 和 `ExportMarketingSystem` 改成了 `ftms` / `ems`。

这个仓库一度还兼着「产物仓库」，`ftms/`、`ems/` 两个目录由各自的项目用脚本推进来。
改成项目站点之后那套跨仓库部署整个不需要了 —— 一个项目一个仓库，各自发各自的。

## 加一个项目

只改 [`sites.js`](sites.js)：

```js
{
  slug: "xxx",                    // 短名。埋点靠它区分「点了哪个项目」
  cat:  "ext",                    // 分类，取 CATEGORIES 里的 key
  name: { zh: "项目名", en: "Name" },   // 中英文同名就写一个字符串
  desc: { zh: "一句话说清它替谁解决什么", en: "…" },
  tags: { zh: ["关键词"], en: ["Keyword"] },
  icon: "/xxx/favicon.svg",       // `/` 开头当图片；否则取 ICONS 里的图形 + tint 上色
  href: "/xxx/",                  // 有在线地址才写。写了就自动排前面、占两格、带「在线」徽标
  repo: "xxx",                    // GitHub 仓库名
}
```

分类、筛选、搜索、中英文、埋点全跟着数据走，`index.html` 一个字都不用动。

**图标优先借子站自己的 favicon**（`/xxx/favicon.svg`），不要拿 emoji 顶替 ——
图标是产品的脸，首页摆一个跟站内对不上的，第一眼就露怯；借它自己的还能永远不跑偏。
没有 favicon 的（扩展、脚本、App）用 `ICONS` 里的线条图形配 `tint` 上色：
emoji 在 Windows / Mac / Android 上长得完全不一样，一排摆开必然花。

两件容易忘的配套：

- 新项目如果是**单页应用**，把前缀加进 `sites.js` 末尾的 `SPA_PREFIXES`，否则深链接刷新会 404
- 新项目如果有 **sitemap**，在 `robots.txt` 里加一行 `Sitemap:` —— 爬虫只读根目录这一份

## 几个不显眼但重要的地方

**深链接兜底。** `/ftms/` 是单页应用，刷新 `/ftms/follow-ups` 会走 404 流程。正常情况下
Pages 回落到那个项目站点自己的 `404.html`，走不到这儿。但「Pages 会不会替子目录去找最近的
404.html」官方说得并不硬，一旦不这么做就是**所有深链接刷新全 404**。所以 `404.html` 里补了
一道：把原始路径记进 `sessionStorage` 再跳回子站首页，应用启动时 `replaceState` 还原。
其中 `p !== prefix` 那半句是防死循环的 —— 少了它，子站真挂掉时浏览器会一直转圈。

**访问统计。** 首页和各子站共用同一个 GA4 property（`G-Y7H2JMNX74`）。同域下 GA4 靠域名级
`_ga` cookie 认人，一个 property 才能把「从首页点进 ftms、退出来又去了 ems」看成一次会话、
一条路径。分站靠 `site` 参数和 `page_path` 前缀在报表里切开。开了「请勿跟踪」就不发。

**版权邮箱画在 canvas 上。** 页脚那个邮箱不是文本节点，源码里也没有可直接正则捞走的字面量，
更没写进 `aria-label` / `title`。邮箱以文本形态出现在公开网页上，半天就会进群发名录。
补偿：整块可点击复制，读屏用户拿到的是可粘贴的真地址，而爬虫不会去点按钮。

**中英文。** 默认跟浏览器语言走（`navigator.language` 不是中文就开英文），
手动切过就记住，之后不再猜。界面词条在 `index.html` 的 `I18N` 里，
项目自己的名字和描述在 `sites.js` 里 —— 谁的文案归谁管。

**子站一律新标签打开**（`target="_blank"` + `rel="noopener noreferrer"`）。
入口页的作用是分发，不是拦路：从这儿点走的人多半还要回来看第二个。

**这一页只做一件事：把人分发到各个项目去。**
曾经加过戳泡泡、连连看、极光背景、指针跟随高光，都拿掉了 ——
入口页多一个玩意儿，主线就模糊一分。

## 首页为什么长这样

**排成一页目录，不是一墙卡片。** 12 个项目一屏就能扫完，卡片墙反而把跨度极大的
东西（外贸系统 ↔ 老爸象棋）摆成了同质的商品堆。这一页当文档排：正文、列表、
一格预览窗，没有卡片、没有按钮墙。装饰预算只花在三个地方，多一处都不加：

1. **介绍句里的数字就是筛选器。** 「5 个浏览器扩展」本身是个按钮，点了列表只亮这一类。
   筛选器不是一排胶囊，是一句话。连「十二个」这种中文数字也是数出来的
   （`zhNum` / `enNum`），加项目照样只改 `sites.js`。
2. **右侧一格预览窗**，跟着悬停和键盘焦点换内容。
3. **换明暗时从按钮荡开的那个圆**（View Transitions）。浏览器不支持就直接切，什么都不少。

**筛选是压暗，不是移除。** 版面不跳动，序号也还认得出谁在哪一位。
压暗的行同时设 `inert` —— 看不见的东西不该还能被 Tab 到、被读屏念到。
筛到靠后的分类时，匹配的行可能整个在屏幕外，看着像「全没了」，
所以**只在第一条匹配确实不在视口里**时才滚过去；本来就看得见就一动不动。

**每一行自带两个去处。** 行本身去「能用的那个地方」（有在线地址就去在线，
没有就去源码），行尾那个 GitHub 图标单独去源码。两种行的图标落在同一列：
在线项目是 `↗` + 可点的 GitHub 链接，非在线项目没有箭头、GitHub 只是个标记
（点它照样走整行热区去源码）。

**整行可点，但链接名只有项目名。** 热区是 `.nm::after` 铺出来的，
描述留在链接外面当正文 —— 读屏拿到的链接名就是「信风 Tradewind」，
而不是把整段描述连着分类一起念一遍。

**预览窗里一个链接都不放。** 它整块是 `aria-hidden` 的（内容在左边每行里都有，
读屏不用听两遍），而 `aria-hidden` 的容器里藏可聚焦的链接，等于给键盘用户挖坑。

**没有搜索框。** 12 行全在 DOM 里，浏览器自带的 Ctrl / ⌘ + F 比任何自制搜索都好用，
还能搜到描述正文。等项目过 20 个再把 `/` 请回来。

**键盘。** `Esc` 取消筛选。行是链接，Tab 天然能走；走到哪，右边预览窗跟到哪。

**关了 JS 是一页空白。** 清单本来就是从 `sites.js` 渲染的。`<noscript>` 里
不列具体项目 —— 一列就得跟着 `sites.js` 同步，迟早对不上 —— 只把人送到
`github.com/decli`。
